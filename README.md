# Penny: a personal finance agent

Penny reads your bank statements and Splitwise, then **reasons about your money with tools**: how much you can
spend tonight, who still owes you, where you're overspending, and what changed since it last advised you.

It started from a real problem: two bank accounts (one for everyday spending, one for salary and rent), bills
that vary month to month, friends who owe money on Splitwise, and a monthly cap that's easy to blow without
noticing. A budgeting dashboard shows what already happened. Penny answers the question you have right now,
using the current state of all of those sources together.

## Try it

The deployed app runs on **Maya**, a fictional NYC grad student, so anyone can try it without sharing real
statements. Maya has a Chase spending account, a Bank of America salary account, two roommates and two friends
on Splitwise, and a **$1,800 monthly cap that includes $1,250 rent**. Her seven months of statements are
generated by `generate_demo_data.py` and live in `statements/` as ordinary CSV exports, which the app reads at
startup.

The app starts on a simulated date (**Friday, Sep 18, 2026**). **Next day** reveals the next day's real
transactions, so you can watch Penny's advice change as the month plays out. Anything you tell Penny ("I just
spent $30 at Zara") changes only your own session. **Reset** restores the original data.

### Three sample queries

1. **"I'm going out for drinks tonight. How much should I spend?"**
   Penny calls `recommend_spending`. Maya usually spends about $30 on a night out, but she's over on shopping,
   so Penny suggests about $13 and explains why.
2. **"I just spent $30 at Zara. Now how much should I spend on drinks tonight?"**
   Penny records the purchase with `add_transaction`, re-runs the recommendation, and the amount drops (to
   about $9). Ask "why did you lower it?" and it cites the $30 of extra shopping.
3. **"Who still owes me money?"**
   `get_shared_balances` combines Splitwise with the bank: Jordan has owed $48 for 20 days. Priya is marked
   paid in Splitwise but no deposit ever arrived. Alex sent a Zelle that was never recorded in Splitwise.

More to try: *"Where am I overspending?"*, *"Can I afford a $60 dinner this weekend?"*, *"I paid $90 for
dinner with Sam and Priya. Split it."*, *"How much did I spend on dining this month compared with last
month?"*, *"How many small purchases have I made this month?"*

## How it works

```
statements/*.csv ──importer──► seed database (SQLite, built once at startup)
                                     │  copied for each chat session
                                     ▼
 browser ──/chat──► harness loop ──► Gemini ──tool calls──► tools.py ──► finance.py ──► session database
```

**The model never does the math.** Gemini decides which tools to call and explains the results; every number
comes from deterministic Python in `finance.py`, and the system prompt forbids stating any dollar figure that
didn't come from a tool result.

**Facts are stored; conclusions are computed.** The database holds only facts (bank transactions, Splitwise
expenses and payments) and the user's plan (cap, bills, category targets). Balances, who owes whom, money left
in the budget and recommendations are computed on demand, so they can never go stale. The one exception is a
log of past recommendations, which lets Penny explain *why* its advice changed.

**Statements are linked across sources at import:** transfers between Maya's own accounts are paired (so they
are neither income nor spending), Splitwise expenses are matched to the bank charges that paid for them, and
Splitwise payments are matched to Zelle deposits.

**Net-of-split spending.** If Maya pays $90 for a dinner split three ways, her Dining budget counts $30.
Expenses a roommate paid count at Maya's share.

**Adaptive budget.** Category targets start from Maya's average monthly spending, scaled so that bills plus
targets equal the cap. As the month goes on, whatever is left of the flexible budget is shared among categories
in proportion to their remaining room, so overspending in one category (or a higher bill) shrinks every other
category by the same percentage. A recommendation for "tonight" treats tonight as one occasion and divides the
category's remaining room by how many more occasions Maya usually has before the month ends.

**Sessions are separate:** each chat session has its own conversation and its own in-memory copy of the
database.

## Tools

| Tool | What it does |
|---|---|
| `get_financial_position` | Balances per account, total cash, owed to you, you owe, net position, and **spendable cash** (cash minus bills still due and debts; IOUs not counted until paid) |
| `query_transactions` | Search transactions by date, account, category, merchant text, amount, direction |
| `summarize_spending` | Spending grouped by category/merchant/week/day, net of splits; counts small purchases under $15; optional comparison with the same dates last month |
| `get_budget_status` | Cap, spent so far, bills paid and due, per-category target / spent / over / re-balanced room |
| **`recommend_spending`** | *Original.* How much to spend in a category today, this weekend or for the rest of the month, with step-by-step reasons and what changed since the last recommendation |
| **`evaluate_purchase`** | *Original.* What-if for a planned purchase: fits the category, only fits by cutting others, or breaks the cap, and which categories get squeezed |
| **`get_shared_balances`** | *Original.* Who owes whom from Splitwise, how long each balance has been open, **cross-checked against bank deposits** |
| `update_budget` | Change the monthly cap or category targets |
| `add_transaction` | Record a purchase, money received, a transfer between accounts, or a payment to/from a friend |
| `split_transaction` | Split an existing purchase with people (like adding it to Splitwise) |

The database is the external data source: every tool reads or writes the session's SQLite ledger. Tools
validate their arguments and return errors the model can act on, e.g. `Unknown category 'drinks'. Did you
mean: Dining? Valid categories: ...` or `2026-10-01 is in the future. Today is 2026-09-18`.

## Run locally

```bash
gcloud auth application-default login
uv run app.py            # http://localhost:8000
uv run pytest            # engine tests: balances match statements, splits, re-balancing, session isolation
uv run generate_demo_data.py   # regenerate Maya's statements (deterministic)
```

Set `PENNY_MODEL` to use a different LiteLLM model (default `vertex_ai/gemini-3.5-flash-lite`).

## Files

| File | |
|---|---|
| `app.py` | FastAPI app, harness loop (from the course starter), sessions, `/chat`, `/state`, `/next-day`, `/clear` |
| `tools.py` | Tool functions, argument validation, and the JSON schemas the model sees |
| `finance.py` | The engine: spending, budget re-balancing, recommendations, shared balances, position |
| `db.py` | Schema, statement importers (Chase, Bank of America and Splitwise CSV formats), linking, starting plan |
| `generate_demo_data.py` | Writes Maya's statements to `statements/` |
| `index.html` | Dashboard + chat UI with tool calls shown |

## Limitations and next steps

Penny only knows what is in the statements: a Venmo repayment that never reaches a bank account shows up as a
mismatch, not a payment. Categories come from simple merchant rules. Next: importing real Chase/BoA PDF
statements, live Splitwise sync, and proactive alerts.
